# 02 · 使用说明

> 面向使用者与维护者，按部署使用、维护、调试组织。命令清单以 `sh manager.sh help` 为准，代码位置见 `ARCHITECTURE.md`。

## 一、部署与使用

### 环境要求

- Windows 10 或 Windows 11。
- .NET 8 SDK 或兼容的更高版本 SDK。
- Git Bash（运行 `manager.sh` 与 `check-docs.sh`）；也可以直接使用根目录 BAT 脚本。

### 构建与启动

```bash
sh manager.sh build
sh manager.sh start
```

启动后显示主窗口；关闭窗口默认最小化到托盘，可在设置页修改关闭行为。

不使用 Git Bash 时，可运行 `build.bat` 与 `run.bat`；开发时使用 `dev.bat` 重新构建 Debug 并启动，若已有实例运行会先请求正常退出。`status.bat` 查看运行状态，`stop.bat` 只请求正常关闭，绝不强制结束进程。若关闭窗口仅最小化到托盘，请从托盘菜单选择「退出」。

### 基本使用流程

1. 在「软件管理」中扫描运行软件或手动添加可执行文件。
2. 启用软件监听，并按需要选择前台或 Running 统计模式。
3. 返回「概览」查看活跃软件、今日统计和活动时间线。
4. 在「统计分析」切换日、周、月、年和全部时间。
5. 在「时间记录」按软件或来源筛选、补录或修正异常记录；CSV 导出遵循当前日期与筛选条件。
6. 在「设置」调整空闲阈值、语言、主题、开机启动、托盘、全局快捷键、通知和隐私选项。

### 隐私边界

- 默认不持久化窗口标题、文档名或网址。
- 锁屏、休眠、暂停和隐私模式期间不累计有效时长。
- 所有统计数据默认仅保存在本机。

## 二、维护

### 数据目录与文件

默认数据目录为 `%AppData%\AppUsageTracker\`，也可以从设置页打开。主要文件包括：

```text
usage_config.json        应用设置
tracked_apps.json        已配置软件
activity_sessions.json   原始会话（事实数据源）
daily_aggregates.json    可重建的日汇总
manual_corrections.json  手动修正
logs\app.log            运行日志
startup-error.log       启动失败时生成的诊断日志
```

写入采用临时文件与原子替换，并保留 `.bak` 备份；读取损坏时回退备份或默认值。汇总数据可从原始会话重建，不要手工只改汇总文件。

### 备份、恢复与导出

- 设置页可以创建或恢复 ZIP 备份；备份仅包含上述五份业务 JSON，不包含日志、`.bak` 和临时文件。恢复前建议先另行备份当前数据目录。恢复会先停止监听，导入成功后应用自动退出，重新启动后加载备份数据；导入失败会提示并自动继续监听。
- 时间记录页可以导出当前日期及筛选条件下的会话 CSV。
- 数据完整性检查会验证各 JSON 文件是否可以正常解析。

### 测试与文档检查

```bash
sh manager.sh test
sh check-docs.sh
```

UI 或交互改动还应运行 `sh manager.sh start`，人工检查布局、导航、输入控件、主题和托盘行为；`tools/capture-ui.ps1` 可辅助切页截图。

### 打包与发布

仅打包当前版本：

```bash
sh manager.sh pack
```

发布文件生成到 `dist/`。发布目标为 `win-x64` 自包含单文件，Trim 与 ReadyToRun 默认关闭。也可运行 `publish.bat self`（或 `fx`）：先发布到 `.runtime/package/` 并验证单文件，成功后才替换 `dist/`；失败时保留暂存现场供排查。`package.bat` 是同功能别名。

新版本发布时先整理 CHANGELOG，再执行：

```bash
sh manager.sh release <version>
```

该命令会检查工作区、更新主项目版本号并打包，不会自动提交、打 tag 或创建 GitHub Release。

### 清理

```bash
sh manager.sh clean
```

这会清理解决方案构建产物、`dist/` 和项目内 `.runtime/`，不会删除 `%AppData%\AppUsageTracker\` 中的用户数据。`clean.bat` 仅清理仓库内受管路径，检查并拒绝跟随 junction/symlink；检测到应用运行时直接拒绝清理。

## 三、调试与自查

| 现象 | 自查入口 |
| --- | --- |
| 命令无法执行 | 确认在仓库根目录运行；检查 .NET SDK 与 Git Bash 是否在 PATH 中 |
| 应用启动失败 | 查看 `%AppData%\AppUsageTracker\startup-error.log` 与 `logs\app.log` |
| 配置或数据文件损坏 | 先备份数据目录，再检查同名 `.bak`；应用读取时会按持久化策略回退 |
| 统计结果有疑问 | 以 `activity_sessions.json` 为事实来源，结合时间记录页和完整性检查排查 |
| UI 布局或交互回归 | 实跑五个页面，检查明暗主题、导航、滚动、托盘与关闭行为；必要时使用 UI 截图脚本 |
| 协作文档检查失败 | 按 `sh check-docs.sh` 的 FAIL 项修复；语义漂移需另行运行文档审计 |

更多长期代码约束与已知坑见 `ARCHITECTURE.md` §7。
